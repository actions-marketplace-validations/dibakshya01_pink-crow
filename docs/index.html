Why it exists

Attacks don't happen in one message. Your defenses shouldn't reset every turn.

◴

Sessions, not snapshots

A probing attacker tests delimiters, then encodings, then role-play — escalating over many turns. pink-crow keeps a cumulative, time-decayed score that sees the campaign build, not just the last message.

cross-turn scoring
⃠

The neglected risk: cost

Resource exhaustion — token floods, "repeat forever", denial-of-wallet — is the single most-ignored OWASP category in guardrail tooling. pink-crow scores LLM06 as a first-class signal.

LLM06 unbounded consumption
◉

Explainable to a security team

"An ML model said 0.83" isn't defensible in an incident review. Every point of a pink-crow score is deterministic, offline, and replayable — the same input always yields the same verdict.

auditable by design
How it works

Score every message. Act on the session.

01

Inspect

Deterministic detectors scan each input & output — injection, obfuscation, floods, secret egress.

02

Map

Every finding carries its OWASP 2026 & 2025 ID. No guesswork, no black box.

03

Accumulate

Per-event scores roll into a session score that decays over time — a live risk picture.

04

Decide

A policy maps the score to allow · flag · redact · block · session time-out.

05

Emit

A risk header on every message, plus an Agent Control Standard disposition.
